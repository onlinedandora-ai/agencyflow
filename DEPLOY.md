# Production deploy checklist

## 1. Push latest code

```bash
git add -A && git commit -m "Production deploy: glass UI, task SLA, Supabase, Docker API"
git push origin main
```

## 2. Deploy API on Render

1. Open https://dashboard.render.com/select-repo?type=blueprint
2. Connect **vaitahavya/agencyflow** → apply `render.yaml`
3. Set these env vars on **agencyflow-api**:

| Variable | Value |
|----------|-------|
| `DATABASE_URL` | Pooler URL from `apps/api/.env` — **no quotes** |
| `DIRECT_URL` | Session pooler URL — **no quotes** |
| `WEB_ORIGIN` | `https://YOUR-APP.vercel.app` (set after step 3) |
| `JWT_SECRET` | Auto-generated by Render (or use a long random string) |

Do **not** set `PORT` manually — Render assigns it automatically.

**Common mistake:** pasting `"postgresql://..."` with quotes breaks the URL. Paste the raw URL only.

4. Wait for deploy → test: `https://agencyflow-api.onrender.com/health`

## 3. Deploy web on Vercel

1. https://vercel.com/new → Import **vaitahavya/agencyflow**
2. **Root Directory:** `apps/web`
3. **Environment variable:**

```
NEXT_PUBLIC_API_URL=https://agencyflow-api.onrender.com
```

(Use your actual Render API URL.)

4. Deploy → copy Vercel URL (e.g. `https://agencyflow.vercel.app`)

## 4. Link API ↔ Web

1. Render → agencyflow-api → Environment
2. Set `WEB_ORIGIN` to your Vercel URL (no trailing slash)
3. Redeploy API

## 5. Seed production (once)

```bash
cd apps/api
# Use production DATABASE_URL in .env temporarily, or Render shell:
npm run prisma:seed
```

## 6. Verify

- [ ] `GET /health` → `{"status":"ok"}`
- [ ] Login at Vercel URL with `admin@agencyflow.com` / `demo123`
- [ ] Pipeline loads leads
- [ ] Project board loads tasks

## CLI shortcuts

```bash
# Vercel (after vercel login)
cd apps/web
vercel link
vercel env add NEXT_PUBLIC_API_URL production
vercel --prod

# Test API Docker image locally
docker build -f apps/api/Dockerfile -t agencyflow-api .
docker run -p 3001:3001 --env-file apps/api/.env agencyflow-api
```
